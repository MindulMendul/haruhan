# SEO (Search Engine Optimization)

## 한 줄 정의

검색 엔진이 페이지를 **크롤링(수집) → 인덱싱(저장) → 랭킹(노출 순서 결정)** 하는 각 단계에서, 프론트엔드가 할 수 있는 기술적 최적화.

## 카드 요약

- **크롤링**: 검색 봇이 페이지를 발견하고 방문하는 단계. `robots.txt`, sitemap, 내부 링크 구조가 영향을 준다.
- **인덱싱**: 방문한 페이지의 콘텐츠를 검색 엔진이 이해하고 저장하는 단계. 렌더링 방식(CSR/SSR), 메타 태그, 구조화 데이터가 핵심.
- **랭킹**: 저장된 페이지 중 어떤 것을 먼저 보여줄지 결정하는 단계. Core Web Vitals 같은 사용자 경험 신호도 반영된다.
- **FE가 직접 통제 가능한 영역**: 메타 태그, 시맨틱 마크업, 렌더링 전략, 성능(Core Web Vitals), 구조화 데이터, sitemap/robots.

## 크롤링 단계에서 볼 것

- **`robots.txt`**: 크롤러에게 어떤 경로를 수집해도 되는지/안 되는지 알려준다. 실수로 중요한 경로를 `Disallow` 하면 전체가 인덱싱에서 빠질 수 있다.
- **`sitemap.xml`**: 사이트의 모든 인덱싱 대상 URL 목록. 새 페이지를 검색 엔진이 더 빠르게 발견하도록 돕는다.
- **내부 링크 구조**: 다른 페이지에서 링크로 연결되지 않는 "고아 페이지(orphan page)"는 크롤러가 발견하기 어렵다.
- **크롤 예산(Crawl Budget)**: 대규모 사이트일수록 크롤러가 사이트를 도는 데 쓰는 자원이 제한적이라, 중복/저품질 URL이 많으면 정작 중요한 페이지가 늦게 수집될 수 있다.

## 인덱싱 단계와 렌더링 방식

검색 엔진이 페이지를 얼마나 잘 "이해"하는지는 렌더링 방식과 직결된다.

- **CSR만 쓰는 경우**: 초기 HTML에 콘텐츠가 비어 있고, JS 실행 후에야 콘텐츠가 채워진다. 주요 검색 엔진은 JS를 실행해 인덱싱하기도 하지만, 렌더링 큐에 들어가 인덱싱이 지연되거나 일부 콘텐츠를 놓칠 위험이 있다.
- **SSR/SSG**: 최초 응답 HTML에 이미 콘텐츠가 포함돼 있어, 크롤러가 JS 실행 여부와 무관하게 즉시 콘텐츠를 확인할 수 있다. SEO가 중요한 페이지일수록 SSR/SSG가 유리한 이유다.
- **메타 태그**: `<title>`, `<meta name="description">`는 검색 결과의 제목/설명에 직접 쓰이므로 페이지마다 고유하고 구체적으로 작성해야 한다. `canonical` 태그로 중복 URL(쿼리 파라미터 등)을 하나의 정본으로 지정한다.
- **Open Graph / Twitter Card**: 검색 노출 자체보다는 SNS/메신저 공유 시 미리보기 품질에 영향을 준다.

## 구조화 데이터 (Structured Data / JSON-LD)

구조화 데이터는 검색 엔진에게 "이 페이지가 어떤 종류의 콘텐츠인지"를 명시적으로 알려주는 표준 포맷(Schema.org)이다.

```
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "제목",
  "datePublished": "2026-01-01",
  "author": { "@type": "Person", "name": "작성자" }
}
```

- `Article`, `Product`, `FAQPage`, `BreadcrumbList` 같은 타입을 페이지 성격에 맞게 넣으면, 검색 결과에 별점/가격/탐색 경로 같은 **리치 스니펫**이 노출될 확률이 높아진다.
- 텍스트로는 사람이 이해하지만 기계는 애매하게 해석할 수 있는 정보(가격, 평점, 날짜)를 명확한 스키마로 못박아준다는 점이 핵심 가치다.

## Core Web Vitals와 랭킹

Google은 사용자 경험 지표를 랭킹 신호 중 하나로 반영한다.

- **LCP(Largest Contentful Paint)**: 가장 큰 콘텐츠가 그려지기까지의 시간. 렌더링 차단 리소스 축소, 이미지 최적화, 서버 응답 시간 단축으로 개선.
- **CLS(Cumulative Layout Shift)**: 레이아웃이 얼마나 튀는지. 이미지/광고 영역에 치수를 명시하고, 폰트 로딩으로 인한 레이아웃 밀림(FOIT/FOUT)을 관리해 개선.
- **INP(Interaction to Next Paint)**: 상호작용 후 다음 프레임까지 걸리는 시간. 무거운 메인 스레드 작업을 줄이고 이벤트 핸들러를 가볍게 유지해 개선.

랭킹에 미치는 영향은 콘텐츠 품질/관련성보다는 작지만, "같은 품질의 콘텐츠라면 더 빠른 페이지가 유리하다"는 타이브레이커 역할을 한다.

## 기술적 SEO 체크리스트

1. 페이지마다 고유한 `title`/`description`을 갖는가.
2. 중복 URL에 `canonical`이 걸려 있는가(쿼리 파라미터, trailing slash 등).
3. `sitemap.xml`/`robots.txt`가 최신 라우트를 반영하는가.
4. 시맨틱 태그(`h1`~`h6`, `nav`, `main`, `article`)로 문서 구조가 명확한가.
5. 이미지에 `alt` 텍스트가 있는가(접근성 + 이미지 검색 노출).
6. 모바일 뷰포트/반응형이 제대로 동작하는가(모바일 우선 인덱싱).
7. Core Web Vitals(LCP/CLS/INP)가 임계값 안에 드는가.
8. 404/리다이렉트 체인이 과도하게 길지 않은가.

## 면접 포인트

1. **크롤링/인덱싱/랭킹을 구분해서 말한다**: SEO를 뭉뚱그리지 말고 어느 단계 이야기인지 명확히 한다.
2. **렌더링 전략과 연결한다**: CSR/SSR 논의를 SEO 관점으로 다시 설명할 수 있으면 지식이 잘 연결돼 있다는 인상을 준다.
3. **성능 지표를 구체적으로 언급한다**: LCP/CLS/INP를 정의뿐 아니라 실제 개선 방법과 함께 말한다.
4. **체크리스트형 답변을 준비한다**: "SEO를 위해 무엇을 확인하나요?"류 질문에 실무 체크리스트로 답하면 설득력이 높아진다.
